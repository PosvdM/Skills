# 姐妹小队

主 Agent 是姐姐，子代理是妹妹。姐姐额度紧张，所以只负责理解需求、定方案、审核和验收，复杂、耗额度的活派给妹妹。编码流程按 coding-workflow，本 skill 只管谁来做。

只在 pi 中用。在 Claude Code、Codex 等 Agent 里不要拿它们自带的子代理代替：用的还是同一家模型，省不了额度。

用 pi-web-ui 自带的 `subagent` 工具派妹妹，不用子代理模板。如果你收到的任务书里写着你是子代理，你就是妹妹：不要加载本 skill，直接按任务书做事。

## 什么时候派

读大量文件或日志、大范围扫描、改多个文件、反复测试调试、排查路线长、长篇写作，这类活派给妹妹。定方案之前的摸底排查也算：要读一大片源码、翻依赖、查日志才能定方案时，派只读的妹妹去查，姐姐看结论定方案，不要觉得“还没开工”就自己查。几条命令、小改动、简单问答姐姐自己做，派一次的开销可能比直接做还大。拿不准时，选更省姐姐额度的做法。

## 模型

每次派妹妹都在 `model` 参数里写明模型，包括 Claude。要写完整的 `provider/model`，provider 用 pi 里当前启用的（`pi --list-models` 可查）。只写模型名会退回姐姐的模型。

| 用途 | 模型 |
| --- | --- |
| 常规执行：编码、系统操作、排查 | `gpt-6.1-sol` |
| 特别难的任务 | `gpt-6-astra`，很耗额度 |
| 写作：文章、报告、PR 描述、发布说明、评论 | pi 里已启用的最新 Gemini |
| 确实需要 Claude | `claude-opus-5-5` |

`model` 只写 `provider/id`，不加 `:medium` 之类的后缀。加了后缀会找不到模型，子代理会悄悄换成默认模型。妹妹的思考强度跟随姐姐当前的强度，派的时候不能单独指定。

## 先说再派

派之前简单说明派哪个妹妹、用什么模型和思考强度（跟随姐姐当前的设置）、做什么；用 astra 或 Claude 时说明理由。

- 编码任务：写进 coding-workflow 的方案里，方案获同意就是同意派工。会改文件的妹妹等方案同意后再派，只读的随时可派。
- 非编码任务：用 sol 或 Gemini，说一声就开始；用 astra 或 Claude，先等我确认。

## 怎么派

- 用 `subagent(action="spawn", type=..., model="provider/id", prompt=...)`。不传 `template`，也不用 `persist: true`。
- 任务书开头写明：「你是子代理（妹妹），由主对话派来做下面的事。不要加载 sister-squad，不要再派子代理，做完按要求汇报。」后面讲清目标、背景、已定的方案、边界（能动什么、不能碰什么）和怎么算完成。具体怎么做交给妹妹判断，不用写成清单。
- 写作任务给出要遵守的 skill 路径，让妹妹先读：文章、报告、邮件用 `~/.agents/skills/plain-language/SKILL.md`；README、技术文档、PR 描述、发布说明用 `~/.agents/skills/project-docs/SKILL.md`。
- `type` 用来标角色：`explore` 只读摸底，`implement` 改文件、执行和写作，`review` 审查。没有模板，角色的要求要写进任务书，例如只读、只审不改。同一目录同一时间只有一个会改文件的妹妹。
- 派出后用 `wait_all` 等结果。等待被打断时再调用一次，不要反复轮询。
- 提交、推送、开 PR、发评论等对外操作由姐姐按 coding-workflow 做，妹妹不做。

## 非编码任务：姐姐代我审核

系统维护、故障排查修复，由姐姐替我把关：妹妹先只读排查、提出操作清单，姐姐只放行必要且安全的操作，再派妹妹执行，最后确认问题解决、没有副作用。改注册表、驱动、服务、系统设置，卸载软件，批量删除这类高风险操作，先备份或建还原点。

姐姐拿不准的先问我，尤其是删除我的个人文件，或者我可能还要用的东西。

## 验收

姐姐看妹妹的报告，编码任务再看 diff 的关键部分，确认符合方案。有问题发回妹妹修改，姐姐不自己大改。

完成后告诉我：每个妹妹用了什么模型和思考强度（跟随姐姐当前的设置）、做了什么，审核时拦下了哪些操作。
