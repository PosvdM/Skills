# 生成简历 PDF

简历用本地 HTML + CSS 排版，再用 Chrome 或 Edge 的无界面模式打印成 PDF。支持 macOS、Windows 和 Linux。

## 依赖

- Python 3。本文的命令写的是 `python3`，Windows 上换成 `python`。
- Chrome 或 Edge。`build.py` 会自动查找，Windows 自带 Edge。找不到时，用环境变量 `RESUME_BROWSER` 指定浏览器程序的路径。
- 检查步骤：macOS 上 `preview.py` 用系统自带的 PDFKit，不用装依赖。Windows 和 Linux 上需要 PyMuPDF：有 `uv` 时用 `uv run --with pymupdf` 运行，不用安装；没有 `uv` 时，征得用户同意后执行 `pip install pymupdf`。
- 苹方（PingFang SC）。样式按苹方调整，macOS 自带。Windows 和 Linux 上先确认已安装苹方，没有就告诉用户；没有苹方时会改用其他字体，排版和 Mac 上不同，可能超出一页。

## 文件

工作目录是用户存放简历的目录，不知道在哪就问用户。目录结构：

| 文件 | 作用 |
|---|---|
| `简历.md` | 内容的唯一来源，用户自己维护。文件名以用户的为准 |
| `排版/<版本>.body.html` | 每个版本一份一页版正文，从简历.md 压缩而来。默认版本叫 `general` |
| `排版/style.css` | 样式：蓝色双斜杠标题、方块圆点、照片在右上角 |
| `排版/build.py` | 套上头部（姓名、联系方式、照片），生成 HTML 并打印成 PDF |
| `排版/profile.json` | 姓名、联系方式、照片文件名 |
| `排版/photo.jpg` | 证件照，3:4。没有照片就从 profile.json 删掉 `photo` |
| `排版/notes.md` | 版本清单，以及这份简历专门的规则 |
| `<姓名>-简历-<求职意向>.pdf` | 输出，每个版本一份 |

`排版/notes.md` 存在时先读。它和本文冲突时，以它为准。

### 版本

一个版本由三样东西组成：正文 `<版本>.body.html`、标题（姓名后面的求职意向）、输出的 PDF 文件名。多个版本共用 `profile.json`、`style.css` 和照片。

- 只换标题、内容不变时，复用同一份正文，比如 `general` 同时出“后端开发”和“Java 开发”两份 PDF。
- 内容要按岗位取舍时（换掉某个项目、删掉某一节），复制一份正文，起个新版本名，比如 `ai`。取舍时也不能新增事实。
- 每个版本都记进 `notes.md`：正文文件、标题、PDF 文件名、生成命令，以及和 `general` 的区别。后来再更新这个版本时，按记下的区别保持取舍，不要改回 `general` 的内容。

`notes.md` 的写法：

```markdown
- 现有版本：
  - `张三-简历-后端开发.pdf`（标题“后端开发”），正文 `general.body.html`：`python3 build.py general "../张三-简历-后端开发.pdf" "后端开发"`
  - `张三-简历-AI 应用开发.pdf`（标题“AI 应用开发”），正文 `ai.body.html`：`python3 build.py ai "../张三-简历-AI 应用开发.pdf" "AI 应用开发"`。和 general 的区别：用 XX 项目替换 YY 项目。
```

### 第一次使用

`排版/` 不存在时，把本 skill 的 `templates/` 复制过去，然后：

1. `profile.example.json` 改名为 `profile.json`，按简历.md 填上姓名和联系方式。`contact` 里每个子数组排成一行；`icon` 可选 `user`、`phone`、`mail`、`web`、`github`。
2. 先在工作目录里找证件照（比如 `证件照.jpg`），找到就复制成 `排版/photo.jpg`；找不到再向用户要。
3. 参照 `example.body.html` 的结构写 `general.body.html`，然后删掉示例文件。
4. 新建 `notes.md`，写上版本清单。

### 已有排版目录

`排版/` 已经存在时，用 diff 比较 `排版/build.py` 和本 skill 的 `templates/build.py`。内容不同时，告诉用户 skill 里的版本更新了，问要不要换成新的。不要自己覆盖，因为用户可能改过。`style.css` 通常按简历调整过，不做比较。

## 流程

1. **重新读一遍简历.md**，和要更新的各版本正文逐条对照。用户可能改过简历.md，比如删掉某一项、调整列表顺序。
2. **改正文**。规则：
   - 每句话都要能在简历.md 里找到出处。可以删减、合并、换说法，但不能新增事实。
   - 列表照抄简历.md，不要只挑前几项，也不要改变用户排的顺序。`notes.md` 里记下的版本取舍除外。
   - 结构：教育背景（排在照片左侧，放在 `<!-- TOP_END -->` 之前）→ 专业技能 → 项目经历 → 获奖 → 校园经历。简历.md 里没有的部分不写。
   - 项目链接用明文写在标题行右侧（如 `github.com/<用户>/<仓库>`），因为简历要打印。
   - 成绩排名或 GPA 等用户给出数字再加，放在教育背景最上面；没有数字时不留占位。
3. **生成**。第一个参数是版本名，最后一个参数是姓名后面的求职意向：

   ```bash
   cd <工作目录>/排版
   python3 build.py <版本> "../<姓名>-简历-<求职意向>.pdf" "<求职意向>"
   ```

   文件名跟着求职意向走。换了求职意向就生成新文件，不要覆盖其他求职意向的版本，并把新版本记进 `notes.md`。用户改了正文、要更新已有版本时，只重新生成工作目录里现有的 PDF，每个版本用各自的正文和标题。`notes.md` 记录的版本和现有文件对不上时（比如用户删掉了某个版本），先问用户，不要自己补生成。

   浏览器没生成 PDF 时，`build.py` 会输出浏览器的报错，据此排查。

4. **检查**：

   ```bash
   python3 <本 skill 目录>/scripts/preview.py "../<姓名>-简历-<求职意向>.pdf"
   # Windows 和 Linux 没装 PyMuPDF 时：uv run --with pymupdf <本 skill 目录>/scripts/preview.py "../<姓名>-简历-<求职意向>.pdf"
   ```

   脚本输出页数和第 1 页页底的空白，并把每页渲染成 PNG，放到它最后一行输出的目录里（系统临时目录下的 `resume-preview/`）。要求只有 1 页；超过 1 页时，脚本还会输出第 2 页起的文字，据此判断要压缩几行。注意 Chrome 不会让一段文字在页底或页顶只留一行，所以末尾两三行的条目放不下时，往往整条挤到第 2 页。

   页底空白超过两三行，而之前为了排进一页删过内容或调小过行高、间距时，告诉用户还有空间，问要不要放回去。

   查看图片，检查：头部有没有空白，照片有没有压到文字，有没有一段只多出一两个字、单独占了一行。

## 超出一页时怎么压缩

按顺序尝试，每改一步重新生成、检查：

1. 收短只多出几个字的段落，让每条刚好占满整行，同时不改变意思。
2. 合并同类短条目，比如校园经历每项写成一行：`<strong>名称</strong>（起止时间）：内容`。
3. 调 `style.css` 开头的两个变量：`--line-height`（正文行高，默认 1.5）和 `--h2-margin`（一级标题外边距，默认 7px 0 2px）。旧的 `style.css` 没有这两个变量时，直接改 `body` 的 `line-height` 和 `h2` 的 `margin`。字号 11.6px 已经偏小，不要再缩。改过的值记进 `notes.md`。
4. 删掉次要的要点。先删哪条要问用户。

## 排版要求

- 一页纸。
- 在哪台电脑上生成，就在哪台电脑上检查。
- 头部紧凑：姓名一行，下面两行联系方式，照片在右上角，旁边不能留大块空白。
- 完成后说明改了什么，不要只说“已完成”。压缩时删掉的具体信息（例子、数字、名称）要单独列出来，让用户决定要不要换别处压缩。
