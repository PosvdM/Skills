# 姐妹小队

主 Agent 是姐姐，子代理是妹妹。姐姐额度紧张，只负责理解需求、定方案和验收，复杂、耗额度的活派给妹妹。Claude Code、Codex 的子代理和主 Agent 用同一家模型，省不了额度，所以本 skill 只在 pi 中用。

## 什么时候派

- 派：连服务器、读源码、拉数据做统计、写脚本、读大量文件或日志、改多个文件、反复调试、长篇写作，以及定方案前的摸底（派只读的妹妹，姐姐看结论定方案）。
- 不派：几条命令、小改动、简单问答。

"帮我查一下""去看看"这类请求最容易低估，可能越查越深的就派。拿不准时选更省姐姐额度的做法。

## 模型

| 用途 | 模型 |
| --- | --- |
| 常规：编码、系统操作、排查 | `cpa/gpt-6.1-sol` |
| 特别难的任务（很耗额度） | `cpa/gpt-6-astra` |
| 写作：文章、报告、PR 描述、发布说明、评论 | `cpa/gemini-3.8-flash-high` |
| 确实需要 Claude | `cpa/claude-opus-5-5` |

`model` 参数必须写完整的 `provider/id`：只写模型名会退回姐姐的模型，加 `:medium` 之类的后缀会悄悄换成默认模型。思考强度跟随姐姐，不能单独指定。模型下线或改名不一定报错，派出后核对妹妹实际用的模型，不一致就用 `pi --list-models` 查，并更新本表。

## 先说再派

派之前说明派哪个妹妹、用什么模型和思考强度、做什么；用 Astra 或 Claude 要说理由。

- 编码任务：写进 coding-workflow 的方案，方案获同意就是同意派工。会改文件的妹妹等方案同意后再派，只读的随时可派。
- 非编码任务：用 sol 或 Gemini 说一声就开始；用 Astra 或 Claude 先等我确认。

## 怎么派

- `subagent(action="spawn", type=..., model="provider/id", prompt=...)`，不传 `template`，不用 `persist: true`。
- `type`：`explore` 只读摸底，`implement` 改文件、执行和写作，`review` 审查。只读、只审不改等限制写进任务书。同一目录同一时间只能有一个会改文件的妹妹。
- 任务书开头写：「你是子代理（妹妹），由姐姐派来做下面的事。不要加载 sister-squad，做完按要求汇报。」后面写清目标、背景、已定的方案、边界（能动什么、不能碰什么）和完成标准，具体做法交给妹妹。
- 妹妹能看到记忆快照，但快照有截断。环境信息和坑（服务器连接、该用哪个 ssh、路径、账号）仍要写进任务书。
- 要求妹妹在汇报里附上关键命令和输出摘要。
- 派出后不用 `wait_all` 干等（会占住对话），用 `schedule` 定几分钟后回来看结果，然后结束本轮。
- 方案获同意后，提交、推送、开 PR、合并、发版可以派妹妹做。任务书写明分支、tag 和合并方式，禁止 force push 和删改已有的 tag、分支。评论只能原样发出我确认过的定稿。

## 系统维护和故障修复

妹妹先只读排查、列出操作清单；姐姐只放行必要且安全的操作，再派妹妹执行，最后确认问题解决、没有副作用。改注册表、驱动、服务、系统设置，卸载软件，批量删除，先备份或建还原点。拿不准就问我，尤其是删除我的个人文件或我可能还要用的东西。

## 验收

排查类看报告附的命令和输出，不自己再跑一遍；编码任务再看 diff 的关键部分，确认符合方案。有问题发回妹妹改，姐姐不自己大改。

完成后告诉我：每个妹妹用了什么模型和思考强度、做了什么，审核时拦下了哪些操作。
