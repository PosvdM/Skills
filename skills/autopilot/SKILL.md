# 自动驾驶

主人不在电脑前，决定都由你来做，做完发 Bark 通知。主人回来时 prompt cache 早已过期，在原对话里接着聊要把整段上下文重算一遍，所以要问的事和之后要用的信息都写进报告和记忆，让主人开新对话就能接着做。

下文的 `bark.mjs` 指本 skill 目录下的 `scripts/bark.mjs`，需要 Node 18 及以上。

## 开始

1. 建报告 `~/.agents/autopilot/<YYYY-MM-DD>-<主题>.md`，第一行写 `状态：进行中`，按「报告」一节列好各节。
2. 从记忆 `preferences.md` 的「自动驾驶」一节读取 Bark 地址。读不到时不发通知、不启动看门狗，在报告里说明，其余照做。
3. 发一条测试通知，让主人走开前就能确认通知正常：`node bark.mjs send <Bark 地址> "autopilot 已接手" "<任务一句话>"`。
4. 在后台启动看门狗，它不能随本轮结束：`node bark.mjs watch <Bark 地址> <报告路径>`。报告超过 90 分钟没有修改、状态仍是“进行中”时，它会替你发一条通知；状态改成别的后它自行退出，最长运行 24 小时。在 macOS 上它还会阻止系统睡眠，直到自己退出。
5. 回复主人一句：已接手，报告在哪。在 MacBook 上要提醒主人不要合盖，合盖后仍会睡眠（接了外接显示器时除外）。

## 做决定

- 不用 `ask_user_question`，妹妹的提问也不 `escalate`，这两种都会卡到主人回来。由你回答。
- 主人交代了任务，就等于同意了完成它所需的方案；在这次任务范围内，coding-workflow 的"等主人同意"不适用。
- 有几种做法可选时，选能撤回的那种，接着做，并记进报告的「我替你做的决定」：选了什么、为什么、怎么改回去。
- 以下的事不做，写进「需要你定的事」，并附上推荐：
  - 在别人的仓库发评论、issue 或 PR
  - 删主人的文件
  - 改生产服务器
  - 花钱
  - force push，删改已有的 tag 和分支
- 主人自己的仓库，按 coding-workflow 的「交付」一节做完 PR、审查和合并；只有主人交代任务时说了要发版，才发版。
- 一处卡住时，先做不依赖它的部分，不空等。
- 做完只补验证（测试、审查），不扩大范围。新想法写进报告的「建议」。

## 额度

你的额度用完时，这一轮会直接中断，通知发不出去，你也没法唤醒自己。因此：

- 开始前和每两段活之间，用 Lamplighter MCP 的 `list_quotas` 查看你所用模型那一组账号的 5 小时剩余额度。剩余不到约 15% 时，做完手头这一步就收尾：写完报告，状态改为“卡住”，发通知，然后停下。没有 Lamplighter MCP 时跳过这一步，靠看门狗报警。
- 妹妹因额度用完而失败时，按 sister-squad 不重试；你还能继续运行，就按“卡住”收尾。

## 报告

每做完一段就更新报告，这样中途断掉时，磁盘上的报告也是最新的。看门狗按文件的修改时间判断，等妹妹的时间很长时，每次被叫醒也要更新报告。主人看不到对话，报告要能单独读懂：

- 第一行：`状态：进行中`、`状态：已完成` 或 `状态：卡住`，看门狗读取这一行
- 任务：主人的原话和你的理解
- 结果：做了什么，以及相关的提交、PR、分支和文件位置
- 我替你做的决定：每条附上改回去的方法
- 需要你定的事：每条附上推荐和原因
- 没做完的部分，以及现场在哪
- 建议
- 续做 prompt：主人回来后开新对话贴进去就能接着做。写明先读这份报告，以及哪些已获同意、哪些要等主人回答

如果中断的是某个仓库里没做完的编码任务，另按 project-docs 写交接文档，并在报告里链接过去。要长期保留的结论和待定的事，按记忆规则写进记忆。报告里不写密钥。

## 收尾

1. 报告写完后，把第一行的状态改为“已完成”或“卡住”。
2. 发通知：标题写 `[完成] <主题>` 或 `[卡住] <主题>`；正文写一两句结果，以及有几件事需要主人定。通知会经过第三方服务器，不写密钥和账号。
3. 最后一条回复写报告的要点和路径。

## 失败时

结果和预期不符或出错时，保留现场：把进度提交成一个"进行中"的提交，推到分支（不推 main），不回滚；然后写报告、发通知。只有不处理会马上造成更大损失时，才先止损，并写进报告。
