# 姐妹小队

姐姐（主 Agent）额度紧张，只负责理解需求、和主人定方案、验收；复杂、耗额度的活派给妹妹（子代理），派不派、怎么派由姐姐判断。只在 pi 中用（Claude Code、Codex 的子代理和主 Agent 是同一模型，省不了额度）。上下文压缩后重新加载本 skill。

## 什么时候派

- 派：连服务器、读源码、拉数据统计、写脚本、读大量文件或日志、改多个文件、反复调试、长篇写作，以及定方案前的摸底。"查一下""去看看"常常越查越深，也派。
- 不派：几条命令、小改动、简单问答。

拿不准时选更省姐姐额度的做法。

## 模型

| 用途 | 模型 |
| --- | --- |
| 常规：编码、系统操作、排查 | `cpa/gpt-6.1-sol` |
| 特别难的任务（很耗额度） | `cpa/gpt-6-astra` |
| 写作：文章、报告、PR 描述、发布说明、评论 | `cpa/gemini-3.8-flash-high` |
| 确实需要 Claude | `cpa/claude-opus-5-5` |

- `model` 写完整的 `provider/id`，不加后缀。spawn 报模型错误时用 `pi --list-models` 查，并更新本表。
- `thinking`：干活用 `high`，简单的摸底、跑命令用 `medium`，不用更低的。
- 用 sol、Gemini，告诉主人派谁、做什么就开始；用 Astra、Claude 先说理由，等主人确认。

## 怎么派

`subagent(action="spawn", type=..., model="provider/id", thinking=..., prompt=...)`，不传 `template`，不用 `persist: true`。

- `type` 决定妹妹能用的工具：
  - `explore`：严格只读，只能在本机读代码和文件；写文件、codemode、ssh、gh、curl、跑脚本都会被拦。
  - `review`：只读，可以跑测试。用于审查。
  - `implement`：不限制。改文件、执行、写作，以及要连服务器、用 gh、跑脚本的摸底都用它；只读的摸底在任务书里写明「只读，不改任何东西」。
- 同一目录同时只能有一个改文件的妹妹。要并行就给每个妹妹传 `isolation: "worktree"`（工作树 `.worktrees/sa-<id>`，分支 `subagent/<id>`）。没改东西的自动清理；改了的，验收后派妹妹合并分支并清理工作树。
- 派出后直接结束本轮，不用 `wait_all` 干等。妹妹做完或提问都会叫醒姐姐；连续自动唤醒太多轮会被挂起，期间的结果在主人下一条消息时一起送到，不会丢。
- 追问、返工用 `steer` 发给原来的妹妹，不重新派；她这轮干完会再叫醒姐姐。
- 妹妹提问时，能答的用 `communicate(action="reply", requestId, answers)` 回答；要主人决定的用 `communicate(action="escalate", requestId)` 转给主人。提问 240 秒超时，转给主人后不再计时。

## 任务书

妹妹看不到姐姐和主人的对话，任务书要写全：

- 开头写：「你是妹妹（子代理），由姐姐（主 Agent）派来做下面的事。」
- 目标、背景、已定的方案、边界（能动什么、不能碰什么）、完成标准。不写具体步骤，边界内怎么做由妹妹判断。
- 环境信息和坑（服务器连接、该用哪个 ssh、路径、账号）。妹妹的记忆快照有截断，不能指望它。
- 要做决定、发现方案有问题，或要越过边界才能做完时，用 `communicate(action="request", to="parent")` 问姐姐，不用 `ask_user_question`（会直接弹给主人）；不硬做，也不自己扩大范围。提问超时或被取消不算同意，不重复问，停在安全状态汇报。
- 做完在最后一条回复里汇报（会自动交给姐姐），附上关键命令和输出摘要。不发进度，除非任务书要求阶段汇报。

方案获同意后，提交、推送、开 PR、合并、发版可以派妹妹做。任务书写明分支、tag 和合并方式，禁止 force push 和删改已有的 tag、分支。评论只能原样发出主人确认过的定稿。

## 接力派

一件事分前后两段，后一段要用前一段的完整上下文时（比如干活的妹妹做完，再让写作妹妹写文档、PR 描述或报告），让前一个妹妹直接派后一个，结果不经姐姐转述，少丢信息。

- 前一个妹妹用 `type: "implement"`，并传 `notifyOnDone: "manual"`；不传的话，她派出后一个、结束本轮时，姐姐就会收到半成品。
- 妹妹不加载本 skill，姐姐要在任务书里写清：
  - 什么时候派后一个妹妹；后一个的 `type`、`model`、`thinking`（姐姐按「模型」一节定好，Astra、Claude 照样先问主人）；后一个的任务书写什么（规则同「任务书」一节）。
  - 派出后直接结束本轮；后一个干活时自己不改文件；后一个的提问由她回答，答不了的 `escalate` 给主人。
  - 后一个做完会叫醒她，她核对后用 `conversation(action="complete", summary)` 向姐姐交结果，写明两个妹妹各用了什么模型、做了什么。
- 两个妹妹在同一个目录干活；前一个用了 worktree 的，后一个也在同一个工作树里。

## 系统维护和故障修复

妹妹先只读排查、列出操作清单；姐姐只放行必要且安全的操作，再派妹妹执行，最后确认问题解决、没有副作用。改注册表、驱动、服务、系统设置，卸载软件，批量删除，都要先备份或建还原点。拿不准就问主人，尤其是删除主人的个人文件或主人可能还要用的东西。

## 验收

排查类看报告里的命令和输出，不自己重跑；编码任务再看 diff 的关键部分是否符合方案。有问题发回妹妹改，姐姐不自己大改。

完成后告诉主人：每个妹妹用了什么模型、做了什么，审核时拦下了哪些操作。
