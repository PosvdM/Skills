# 姐妹小队

主 Agent 是姐姐，子代理是妹妹。姐姐额度紧张，只负责理解需求、定方案、审核和验收，复杂、耗额度的活派给妹妹。Claude Code、Codex 自带的子代理用的是同一家模型，省不了额度，所以本 skill 只在 pi 中用。

如果任务书里写着你是子代理，你就是妹妹：不加载本 skill，直接按任务书做事。

## 什么时候派

- 派给妹妹：读大量文件或日志、大范围扫描、改多个文件、反复测试调试、排查路线长、长篇写作。定方案前的摸底排查也算，派只读的妹妹去查，姐姐看结论定方案。
- 姐姐自己做：几条命令、小改动、简单问答，派一次的开销可能比直接做还大。

拿不准时，选更省姐姐额度的做法。

## 模型

| 用途 | 模型 |
| --- | --- |
| 常规执行：编码、系统操作、排查 | `gpt-6.1-sol` |
| 特别难的任务 | `gpt-6-astra`，很耗额度 |
| 写作：文章、报告、PR 描述、发布说明、评论 | pi 里已启用的最新 Gemini |
| 确实需要 Claude | `claude-opus-5-5` |

每次派都在 `model` 参数里写完整的 `provider/id`，包括 Claude；provider 用 pi 里当前启用的（`pi --list-models` 可查）。只写模型名会退回姐姐的模型；加 `:medium` 之类的后缀会找不到模型，悄悄换成默认模型。思考强度跟随姐姐当前的设置，不能单独指定。

## 先说再派

派之前简单说明派哪个妹妹、用什么模型和思考强度、做什么；用 Astra 或 Claude 时说明理由。

- 编码任务：写进 coding-workflow 的方案里，方案获同意就是同意派工。会改文件的妹妹等方案同意后再派，只读的随时可派。
- 非编码任务：用 sol 或 Gemini，说一声就开始；用 Astra 或 Claude，先等我确认。

## 怎么派

- 用 pi-web-ui 自带的 `subagent` 工具：`subagent(action="spawn", type=..., model="provider/id", prompt=...)`，不传 `template`，不用 `persist: true`。
- `type` 标角色：`explore` 只读摸底，`implement` 改文件、执行和写作，`review` 审查。没有模板，只读、只审不改这类要求写进任务书。同一目录同一时间只有一个会改文件的妹妹。
- 任务书开头写：「你是妹妹（子代理），由姐姐派来做下面的事。不要加载 sister-squad，做完按要求汇报。」后面写清目标、背景、已定的方案、边界（能动什么、不能碰什么）和怎么算完成，具体做法交给妹妹判断。
- 派出后不用 `wait_all` 干等（会占住对话），用 `schedule` 定几分钟后回来看结果，然后结束本轮。
- 提交、推送、开 PR、发评论等对外操作由姐姐按 coding-workflow 做，妹妹不做。

## 系统维护和故障修复

姐姐替我把关：妹妹先只读排查、列出操作清单，姐姐只放行必要且安全的操作，再派妹妹执行，最后确认问题解决、没有副作用。改注册表、驱动、服务、系统设置，卸载软件，批量删除，先备份或建还原点。拿不准的先问我，尤其是删除我的个人文件或我可能还要用的东西。

## 验收

姐姐看妹妹的报告，编码任务再看 diff 的关键部分，确认符合方案。有问题发回妹妹修改，姐姐不自己大改。

完成后告诉我：每个妹妹用了什么模型和思考强度、做了什么，审核时拦下了哪些操作。
